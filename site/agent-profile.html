Practical guide

A working profile for your AI coding agent.

Updated September 25, 2026

If you keep correcting how your AI agent works, your past sessions may contain useful instructions for its next task. Emulo extracts evidence from supported coding-agent logs and helps turn it into an editable you.md profile: how you make decisions, what you reject, and what you expect before calling work complete.

When is a session-derived profile useful?

Consider Emulo when you already have coding-session history and want recurring preferences to carry into future tasks. For example, repeated requests to show a running result may support a rule to verify behavior before reporting completion. Review the supporting messages before accepting that rule.

A handwritten AGENTS.md, CLAUDE.md or Cursor rule is a good place for instructions you already know. Emulo helps discover patterns you have not collected yet. It uses actual session evidence as its input; those instruction files are not mining sources. Keep project facts and explicit project rules alongside the personal profile.

Session sources and profile destinations are different

  • Logs Emulo can read: Claude Code, Codex, GitHub Copilot CLI, OpenCode and Google Antigravity. Antigravity requires interaction logging to have produced readable transcripts.
  • Agents that can receive a profile: installing and loading are different things. In a host-by-host test on 2026-09-25, a project AGENTS.md (--target agents) reached the model in Codex, verified end to end in one test, and was loaded into OpenCode's instructions, as was --target opencode. Claude Code installs the profile as a skill (--target claude) that it does not reliably open on its own; typing /you loads it. The Codex skill (--target codex) is opened only when a request matches its description. The Cursor and Gemini adapters write the file where those tools look for rules; loading there is not verified.
  • MCP clients: Emulo provides a local server with the load_emulo_profile tool. It serves the profile activated by the agent mining flow, not a you.md installed from RUN_ME.md; with none active, it says so. On 2026-09-25, Claude Code connected and listed the tool; Codex called it and received the no-profile message. Other clients were not tested. Configure your client to call it when the profile is relevant.

Cursor is a profile destination here, not a supported raw-log source in the published CLI. A profile can only have an effect when the agent actually loads it. Installation and loading depend on the host; see the current support matrix.

Start with the released CLI

The published 0.6.7 package requires Python 3.8 or newer. In a Python environment, install it and count your available history without writing anything:

python -m pip install emulo==0.6.7
emulo --dry-run

The dry run prints what it found: sessions, your messages, approximate tokens, how many messages had something redacted, and the paths it would write.

When ready, run emulo. It writes the extracted chunks and RUN_ME.md to emulo-out/ straight away. There is no plan or approval step on this path, because emulo itself makes no model calls; the model work starts when you ask your coding agent to follow RUN_ME.md, which mines the chunks into you.md. Preparing chunks alone does not produce a finished personal profile.

Prefer setup through an agent? The documented skill bootstrap is:

npx skills add ohad6k/emulo@emulo

Then ask your agent to run emulo. On this path the agent shows a read-only mining plan with the planned model calls and waits for your approval before any model work. The repository also documents native plugin installation.

Review, then load the profile

Check the generated rules against their receipts. emulo verify you.md checks whether quoted evidence can be found in the mined sessions; it cannot decide whether a rule is useful or accurately describes you.

For Codex or OpenCode, run this from the project after replacing you.md with your generated profile's path. It adds the profile to the project's AGENTS.md, the route the host test saw reach the model. It writes the whole profile, including verbatim quotes from your sessions, into that folder's AGENTS.md, which is usually committed and shared, so keep that file out of version control or install to a personal folder that is not committed.

emulo --install you.md --target agents --repo .

For Claude Code, use --target claude and then type /you in a session to load it. The same command with --target codex, cursor, gemini or opencode writes it for those agents. The cursor and gemini targets each write the whole profile, quotes included, into the --repo folder (.cursor/rules/you.mdc, GEMINI.md). Those files are usually committed and shared, so keep them out of version control or use a folder that is not committed.

For an MCP client, use the installed emulo command with the argument mcp. A common client configuration is:

{
  "mcpServers": {
    "emulo": { "command": "emulo", "args": ["mcp"] }
  }
}

The MCP server serves the profile activated by the agent mining flow (run emulo or emulo:mine), which lives under ~/.emulo or EMULO_HOME. A you.md from the RUN_ME.md path, installed with emulo --install as above, is not activated there, so the server does not see it. See MCP setup for alternatives.

What stays local, and what reaches a model?

Session extraction, redaction, caches and generated profiles stay on your machine in the local workflow. Mining uses the model you choose: a hosted model receives selected evidence, while a local model can keep that processing on your machine. An agent or MCP client backed by a hosted model can also send loaded profile text to its provider as context.

Secret redaction is best-effort. Inspect extracted evidence and profiles before sharing them. The local engine is MIT licensed and works without an Emulo account; model-provider usage can still cost money. This guide covers the local workflow. Consult the security policy for its data boundary.

What to expect

Sparse history can produce a sparse profile. A mined preference can be wrong, outdated or specific to one project. Edit the result and keep only rules you can defend. Emulo does not enforce agent behavior or guarantee that a model follows every instruction.

Evaluate it on your own recurring tasks: check whether the agent loaded the profile, whether it honored the relevant instructions, and whether the result improved. This guide makes no benchmark or recommendation-ranking claim.
